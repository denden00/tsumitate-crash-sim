## 1. プロジェクト概要

積立投資シミュレーションに「暴落シナリオ」を組み込んだ特化型ツールサイト。証券会社の標準シミュレーターにはない「暴落が来たらどうなるか」を可視化する点がコア価値。

## 4. 機能要件

### 4.1 コア機能：積立シミュレーション

**入力**
- 運用期間（年数）
- 想定利回り（年率、%）
- 初期投資元本（任意、一括投資分がある場合）
- 拠出プラン（4.4参照）

> **金額の入力単位は「万円」に統一する（2026-08-26 変更）。** 円単位だと桁が多く入力しづらいため。
> 内部計算は円で行い、UIの境界（`js/ui.js`）で ×10000 して計算ロジックに渡す。

**計算**
- 複利計算による資産推移（月次グリッド）

**出力**
- 資産推移グラフ（時系列）— 結果セクションの最上部に置く
- 元本／運用益の内訳

**想定利回りの参考値（2026-08-26 追加）**

想定利回りの入力欄のそばに、指数ごとの年平均リターン（実績CAGR）を並べて表示する。
クリックするとその値が想定利回り欄に入る。データは `data/index-stats.json`。

- 現地通貨ベース（為替の影響を含まない）
- ETFで代用している指数は分配金込み、指数そのものは配当を含まない価格リターン
- 取得できる期間が指数ごとに違うため、**対象期間を必ず併記する**

### 4.2 暴落シナリオ機能

**入力**
- 暴落発生タイミング（積立開始から何年後）
- 暴落イベント選択（4.3参照）

**計算ロジック（確定・重要）**

> 「暴落からの回復は、あらかじめ決めた想定利回りで一律に上昇していく想定か？」という問いに対し、「実際の暴落の回復期間と回復時の利回りで再現したい」というご回答。つまり、**暴落〜回復の区間は想定利回りを使わず、実データをそのまま反映する**方式に確定。

- **通常期間**（暴落発生前／実データでの回復完了後）：ユーザー入力の想定利回り（年率）で複利計算
- **暴落発生〜回復完了までの期間**：想定利回りではなく、**選択した暴落イベント・指数の実際の値動き（実データ）をそのまま資産推移に反映**
  - データ粒度は**月次**で確定（データ量・取得の手間を抑えつつ、暴落・回復の傾向を再現できる粒度として採用）
  - 例：「リーマンショック × S&P500」を選択した場合、実際の暴落開始月から指数が暴落前水準まで回復した月までの、実際の月次騰落率をそのまま資産評価額に適用する
  - 積立は停止しない前提のため、この期間も毎月の拠出を継続し、実際の価格水準で口数を買い増す（ドルコスト平均法効果を実データで再現する）
- **回復完了後**（実データ上の回復日以降にシミュレーション期間が続く場合）：再びユーザー入力の想定利回りでの複利計算に戻る
- **「回復完了」の判定基準（確定）**：選択した指数が、暴落前の高値を上回った日をもって回復完了とする（資産評価額や積立元本を基準にはしない。指数ベースなのでユーザーの積立ペースに左右されずシンプルに判定できる）

**複数回の暴落（2026-08-26 追加）**

暴落は1件に限らず、期間内に複数回配置できる（UIからは最大5件）。

- 各暴落は「指数 × イベント × 発生タイミング（開始から何年後）」の組で指定する
- **期間が重なる指定は計算から除外する。** 前の暴落が高値を回復し切る前に次の暴落を置く指定は、
  2つの実データを重ねて適用する妥当な方法がないため。除外した理由（`overlap` / `out_of_range`）と
  「何年後以降なら置けるか」を結果画面に表示する
- 指数はそれぞれの暴落ごとに選べる（同一である必要はない）

**暴落の規模の提示（2026-08-26 追加）**

暴落イベントの選択肢（コンボボックス）に、**選択中の指数での月次終値ベースの下落率と高値回復期間**を
併記する（例: `リーマンショック（−53%・回復5年5ヶ月）`）。選んだあとも、行の下に固定スケール
（下落80%を上限）のバーで規模を示し、暴落どうしの大きさを比べられるようにする。

下落率は指数によって変わるため、**UI上は指数の選択を先、イベントの選択を後**に置く。
指数を変えると、イベントの選択肢はその指数で実データがあるものだけに絞られる。

**出力**
- 暴落あり／なし比較グラフ（暴落を経験しない場合＝想定利回りのみで推移した場合との比較）
- 暴落1件ごとの内訳カード（指数の下落率／指数の回復期間／資産評価額の最大下落／資産がピークに戻るまで）
- 実際の元本回復までの期間（実データに基づく実測値）

> 資産評価額のドローダウンは、その暴落の期間内でピークを走査して測る。暴落の初月はまだ拠出で
> 評価額が伸びることがあり、「暴落開始直前の月」に固定すると下落幅を取りこぼすため。
> 取り崩し期間が暴落期間と重なっている場合は、その旨をカードに注記する
> （暴落単独の影響ではなくなるため）。

| リーマンショック | 2008年〜 |
| コロナショック | 2020年 |
| トランプショック | 2025年（関税ショック等） |
| ブラックマンデー | 1987 |
| アジア通貨危機 | 1997 |
| ロシア危機・LTCM破綻 | 1998 |
| チャイナショック | 2015-2016 |

| SVB破綻・米地銀危機 | 2023 |

※東日本大震災ショック（2011）は今回は見送り

**確定指数（7件）**：S&P500／TOPIX／日経平均／オルカン相当（ACWI）／NASDAQ100／MSCIエマージング／MSCIコクサイ（除く日本の先進国）

**機能仕様**

- イベント選択UI（ドロップダウン。選択中の指数で実データがあるものだけを表示し、規模を併記）
- イベント×指数ごとの実データ（下落率・下落期間・回復期間）を事前にCSV取得→JSON変換し、静的データとしてサイトに同梱

### 4.4 拠出プラン：積立・停止・取り崩し（2026-08-26 追加）

積立だけでなく、**積立を止める期間**と**取り崩す期間**を期間ごとに設定できる。

**入力**
- 1件目は必ず「開始時から」で固定。2件目以降は「N年後から」で開始年を指定する
- 各期間の種別は **積立 / 停止 / 取り崩し** の3つ
- 金額は「毎月◯万円」。停止のときは入力不要

**計算**
- 開始年でソートし、次の期間が始まるまでその内容が続く
- **取り崩しは負の拠出として扱う。** 暴落期間中であってもその月の実際の価格で売却する
  （安値で売る＝口数が多く減る、という実データの効果をそのまま反映する）
- **資産を超える取り崩しはできない。** 出せる分だけ取り崩し、残高はマイナスにしない。
  資産が尽きた月を記録し、グラフに縦線で示すとともに結果画面で通知する
- 「元本」は**純拠出額（初期元本 + 累計拠出 − 累計取り崩し）**として扱う。
  取り崩しが進むとマイナスにもなるため、グラフのY軸は下限を0に固定しない
- 運用益 = 最終評価額 − 純拠出額

> **「継続 vs 停止」の2本立て比較機能は引き続き作らない（3.①の判断を維持）。**
> 停止・取り崩しはあくまで「ユーザーが指定した1本のプラン」であり、比較軸は「暴落あり／なし」のみ。

## 5. 非機能要件・技術選定

### 5.1 アーキテクチャ

- **静的サイト**（クライアントサイド計算のみ、サーバーサイド処理なし）
- 過去指数データは事前に取得・整形し、JSONとして同梱
  - 暴落データ: `data/fetch-data/fetch.js` で取得 → `build-events-json.js` で `data/events.json` を生成
  - 利回り参考値: `data/fetch-data/fetch-index-stats.js` で `data/index-stats.json` を生成
    （指数ごとの全期間CAGR。読み込みに失敗しても参考表示が出ないだけでシミュレーションは動く）

### 5.2 データソース

- **Stooq**（`https://stooq.com/q/d/l/`）は検証の結果、不採用とした
  - CSVダウンロードエンドポイントにProof-of-Work型のJSチャレンジがあり、これ自体は自動突破可能なことを確認したが、突破後もエンドポイントが `Access denied` を返し続けた
  - ブラウザでの手動アクセスでもチャート画面からCSVダウンロード導線が確認できず、実運用に耐えないと判断
- **Yahoo Finance**に変更
  - 内部chart API（`https://query1.finance.yahoo.com/v8/finance/chart/<ticker>`）がcrumb等の認証なしで
    月次OHLCVのJSONを返すことを確認し、`data/fetch-data/fetch.js` による自動取得を実現した
  - ブラウザの履歴データページ（`https://finance.yahoo.com/quote/<ticker>/history`）経由の手動ダウンロードも
    フォールバックとして用意（`generate-urls.js`）
  - 公式APIではないため、こちらも**事実上サイト側の実行時には毎回取得せず、事前にJSON化して同梱**する方針は変わらない
  - ティッカー：S&P500=`^GSPC`、NASDAQ100=`^NDX`、日経平均=`^N225`
  - ETFによる代用：ACWI=`ACWI`（設定2008）、MSCIエマージング=`EEM`（設定2003）、
    TOPIX=`1348.T` MAXIS TOPIX ETF（設定2009）、MSCIコクサイ=`TOK` iShares MSCI Kokusai ETF（設定2007）
  - ETF代用の指数は、そのETFの設定日より前に発生したイベントとは組み合わせられない
    （該当組み合わせは間引き済み。詳細は `data/fetch-data/README.md`）
- 拡張候補イベント・指数について、遡れる年数の制約がないか個別検証が必要（特に1987年ブラックマンデーなど古いデータ）

### 5.3 ホスティング

**GitHub Pages に確定**（GitHubリポジトリとの連携がしやすく、GitHub Actionsでのビルド自動化とも相性が良いため）

| | GitHub Pages（採用） | Netlify（不採用） |
|---|---|---|
| 費用 | 完全無料 | 無料枠で十分 |
| リポジトリ連携 | GitHubと直結、Actionsでビルド自動化しやすい | Gitリポジトリ連携可、ビルド設定がやや柔軟 |
| 独自機能 | シンプル | デプロイプレビュー、フォーム機能等が簡単 |
| 広告掲載（AdSense）審査 | 差なし | 差なし |

### 5.4 フロントエンド技術スタック

**素のJavaScript に確定**（学習コストを抑え、シンプルな静的サイト構成を維持する方針）
